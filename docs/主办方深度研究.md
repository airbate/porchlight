## 一、赛事本质：一场「生态赤字」对冲

这个赛不是品牌营销黑客松。Amazon 五条业务线各自面临一个**生态缺口**，办赛的真实目的是用奖金向开发者**采购生态内容**：

| 业务线 | 2025-2026 战略处境 | 办赛真实目的 | 热度预判 |
|---|---|---|---|
| **Ring** | 正在建第三方 **Ring Appstore**（认证上架管线已就绪：Draft→Testing→Certification→Beta→Prod→Live，含变现） | Appstore 冷启动：没有第三方应用，客户不会把门铃当平台 | **中低** ← 我们的主场 |
| **Bee** | 2025-07 收购的 $49.99 全天候录音腕带（Panos Panay 设备线，Halo 2023 砍掉后的穿戴重启），急需「杀手场景」证明全天候 AI 伴值的正当性 | 用开发者创意对冲隐私争议、找产品方向 | 中低 |
| Alexa+ | agentic 语音助手转型（Nova + Claude 驱动），成败取决于第三方 skills/MCP 生态能否冷启动 | 采购第一批 Agent Skill / MCP Server | **最高**（正面战场，已弃） |
| Fire TV | Vega OS 去 Android 化，2017 级别的 app gap 危机 | 采购 Vega 原生应用填补生态 | 高（需真机，已弃） |
| AWS | Bedrock/AgentCore/Strands/**Kiro**（agentic IDE，"Kiro Crew 单独参赛即合格"说明是 2026 主推） | 拉新采用 + 对冲对 Anthropic/OpenAI 的收入依赖 | 中 |

**推论 1**：给哪条线补上它最缺的东西，哪条线的评委就有理由给高分。Ring 线最缺的是「证明门铃可以变成看护平台」的应用——**caretaking 类是我们官方盖章的差异化**。
**推论 2**：AWS Builder 迷你挑战本质是推广 KPI，评分逻辑是「Bedrock/AgentCore/Kiro 用得多深、文档写得让内部团队能拿去汇报」。

## 二、评委画像与投票心理（基于机制的推断）

- 评委 = 各业务线 PM/BD + Devpost 运营（官方"qualified panel"未公布，11 月评审）。他们要向内部证明自己这条赛道的 ROI。
- 因此他们必然奖励三类东西：
  1. **平台独特能力的展示**——离开 Ring/AWS 就做不出来的功能（而不是换皮通用 App）；
  2. **真实运行的 demo**——阶段一就筛「运行时真实调用」，视频必须是目标平台上的实拍；
  3. **可持续叙事**——"黑客松之后还能变成什么"（Ring 线尤其想看到「能上架 Appstore」的路径感）。
- Friction Log 的内部逻辑：这是**免费的用户研究**，Amazon 内部团队真会看。写得好 = 态度分 + 专业度分，最高 +10%，是单人参赛者对抗团队的最高杠杆。

## 三、Ring 线一手情报（2026-09-12 developer.ring.com 抓取）与打法修正

**平台已给的能力（不要重复造）**：
- 事件 webhook，**边缘侧已自带 human / animal / vehicle 三分类**
- 实时视频 WebRTC（WHEP，仅视频无音频）、门铃按键、设备状态、事件历史 API
- 官方 Ring MCP Server（供 Kiro/Cursor/Claude 等 AI 编码工具检索 API 文档、生成代码）

**接入路径（修正了档案里"模拟器"的表述）**：
- 注册入口：`developer.amazon.com/ring`；测试靠 **self-serve sandbox + Ring test account**（门户页未出现"simulator"字样， hackathon 页承诺的模拟器形态待 M0 实证）
- 认证：用户在 Ring App 授权 → authorization code 换 Bearer token；webhook 带 HMAC 签名验证
- **订阅门槛**：页脚注明 "Compatible Ring subscription required"（部分能力可能挂 Ring Protect 订阅）——**M0 必须问清 test account 是否自带**

**对 PorchLight 的三条修正**：
1. **差异化红线**：绝不重建 human/animal/vehicle 分类。我们的价值是**其上的看护层**——滞留时长理解、跌倒姿态、节律异常、大白话家属沟通，这些平台没有、caretaking 优先类别正中。
2. **演示叙事升级**：Demo 要演示「事件进来 → 看护判断 → 家属收到」的全链路，并明确讲出"这条路可以走到 Ring Appstore 上架"（即使赛期内不真上架，路径感就是 PM 们的 KPI 语言）。
3. **Bedrock 选型信号**：全部用 Amazon Nova 家族（不用第三方模型），AgentCore 若时间允许包一层——AWS 迷你挑战评分看的是 Amazon-first 深度。

## 四、拿奖倒推：七条战术（并入里程碑执行）

1. **demo 视频 = 评委的 90 秒平台价值陈述**：前 20 秒必须出现 Ring 事件真实触发（test account 实拍），而非 PPT。
2. **文案里点名官方优先类别原词**（caretaking / accessibility / aging in place），让评委一眼看到"这是给我们赛道做的"。
3. **AWS 集成文档按"可内部转发"标准写**（Bedrock Nova + S3 + EventBridge 逐个写清用了什么、解决了什么、体验如何）——迷你挑战评委很可能直接拿去做汇报素材。
4. **Friction Log 写到"内部团队能拿去改文档"的深度**：每条 = 复现步骤 + 期望 vs 实际 + 建议；目标 ≥10 条高质量。
5. **Product Feedback 必交且分工具写**（Ring API / Bedrock / EventBridge / Devpost 各一条以上）。
6. **可选彩蛋（仅 M2 提前完成时）**：把 PorchLight 包一个最小 MCP server，演示 "Alexa，问问 PorchLight 我爸妈门口今天怎么样"——不投 Alexa+ 赛道，但这段 15 秒画面会同时打动 Ring、Alexa+、AWS 三方评委。
7. **盯 updates/discussions 页**（每周一查）：评委名单、模拟器/沙箱资源、Q&A 中透露的评审口径，全部同步进本档。
