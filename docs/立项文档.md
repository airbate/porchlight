## 1. 项目名

**PorchLight**（门廊灯）

> 命名意象：在美国文化里，"把门廊灯留着"（leave the porch light on）是家人等另一个人平安回家的暗号。PorchLight 把这个意象变成产品：你不在父母身边时，AI 替你守着那盏灯。

## 2. 一句话价值主张

把 Ring 门铃变成独居老人的 24 小时 AI 守门人：自动识别访客、包裹、异常滞留与跌倒姿态，用大白话向远方家属推送「今日门口报告」，紧急情况秒级告警——让父母安心独居（age in place），让子女安心工作。

## 3. 核心功能（3 条）

| # | 功能 | 说明 | 对应评审维度 |
|---|------|------|------------|
| 1 | **Doorstep Sense 门口事件理解** | Ring 事件帧（模拟器/真机）→ Amazon Bedrock Nova 多模态分析 → 结构化分类：访客 / 包裹投递 / 长时间滞留 / 跌倒姿态 / 环境噪音（树枝、光影、过路车），噪音自动过滤不扰民 | Tech Implementation |
| 2 | **Care Digest 看护日报** | 每日定时把当天门口事件生成为一段自然语言摘要（"今天上午有快递、下午邻居来访 20 分钟"），叠加**活动节律异常检测**（如超过 24 小时无人进出）推送家属 | Potential Impact / Quality of Idea |
| 3 | **Instant Alerts 秒级守护警报** | 高置信紧急事件（疑似跌倒、深夜陌生人滞留）在秒级推送给指定家属，附现场快照 + AI 摘要 + 一键行动建议（致电邻居 / 呼叫急救） | Design（符合直觉的看护交互） |

## 4. 技术架构

```
┌─────────────────────────────────────────────────────────────┐
│  数据源层   Ring 模拟器 / Ring 真机（官方 API/SDK，M0 周核实）      │
└──────────────┬──────────────────────────────────────────────┘
               │ webhook / 轮询（事件 + 门铃帧图像）
┌──────────────▼──────────────────────────────────────────────┐
│  感知层    FastAPI ingest 服务                                │
│    · 快照存 S3（可留空跑本地模式）                                │
│    · Amazon Bedrock Runtime（Nova Lite 多模态）→ 结构化 JSON     │
└──────────────┬──────────────────────────────────────────────┘
┌──────────────▼──────────────────────────────────────────────┐
│  业务层                                                      │
│    · 事件存储（SQLite 起步，接口兼容 DynamoDB）                    │
│    · 规则引擎（置信度阈值 / 静默时段 / 防轰炸）                     │
│    · 定时日报（EventBridge Scheduler → digest 生成）             │
└──────────────┬──────────────────────────────────────────────┘
┌──────────────▼──────────────────────────────────────────────┐
│  展示层    React + Vite PWA「家属看板」                          │
│    · 实时事件流 / 今日日报 / 警报中心 / 一键行动                    │
└─────────────────────────────────────────────────────────────┘
```

**技术栈清单**

| 层 | 选型 | 备注 |
|---|------|------|
| 后端 | Python 3.12+ / FastAPI / uv | ingest + 分析 + 业务 API 一体 |
| AI | Amazon Bedrock Runtime（`Converse` API，Nova Lite 多模态） | AWS Builder 迷你挑战核心；文本摘要同走 Bedrock |
| Ring 接入 | 官方 Ring API/SDK + **官方模拟器**（物理设备可选） | 硬性要求：运行时真实调用；M0 周核实确切工具链 |
| 存储 | SQLite（开发）→ DynamoDB（可选上云） | 快照 S3，保留期可配（隐私最小化） |
| 定时 | EventBridge Scheduler（上云后）/ APScheduler（本地） | 日报生成 |
| 前端 | React + Vite + TypeScript PWA | 家属看板 |
| 开源协议 | Apache-2.0 | 满足提交物"可检测开源许可证"要求 |

**AWS 集成点（AWS Builder 迷你挑战申报用，详见 docs/aws-integration.md）**
1. Bedrock Runtime：Nova Lite 多模态门口事件分析 + 日报文本生成
2. S3：门口快照存储（生命周期 7 天自动清理）
3. EventBridge Scheduler：每日看护日报定时任务
4. （可选加分）IAM 最小权限、 Secrets Manager 存 Ring 凭据

## 5. 为什么能赢（评审四维度映射）

- **Tech Implementation**：Ring API 运行时真实调用（非 README 提及）；Bedrock 多模态结构化输出；可离线运行的降级设计让 demo 稳定。
- **Design**：为"远方子女"设计的看护流——日报免打扰、警报必达、一键行动，交互符合 Ring 用户的家庭场景直觉。
- **Potential Impact**：美国 29% 的 65+ 老人独居（约 1,600 万人），"远程看护父母"是 Ring 已有用户的真实高频焦虑；产品在黑客松之外有清晰的订阅化路径。
- **Quality of the Idea**：caretaking / aging-in-place 是 Ring 官方优先类别中参赛者最容易忽视的方向；"porch light" 叙事有记忆点。

**差异化红线**（2026-09-12 研究后确立）：Ring 平台已自带 human/animal/vehicle 边缘分类与事件 webhook——**绝不重建平台已有能力**。PorchLight 只做平台没有的「看护层」：滞留时长理解、跌倒姿态、活动节律异常、大白话家属沟通。同时用 Amazon Nova 全家桶做模型选型（不引第三方模型），贴合 AWS Builder 挑战的 Amazon-first 评分偏好。详见 `docs/主办方深度研究.md`。

**加分项**：全程记录 Friction Log（Ring 工具链 + Bedrock 上手痛点），提交时换最高 10% 加分。

## 6. 风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| Ring 开发者工具链形态未核实（模拟器获取方式、API 是否收费） | 高 | **M0 第 0 周第一优先级核实**；降级路径：用 hackathon 提供的模拟器资源；再降级：转向 Bee 或 Alexa+ 方向（9/18 为 go/no-go 决策点） |
| 中国大陆访问 AWS Bedrock / Ring 门户的网络与账号摩擦 | 中 | AWS 全球区账号 + 提前申请 $150 credits（10/21 PT 截止）；所有外网依赖集中在 config |
| Bedrock 模型访问需要开通（model access） | 低 | M0 周一并开通 us-east-1 的 Nova 系列 |
| 英文 3 分钟视频是额外工作量 | 中 | M3 周预留整 5 天；脚本先行、分镜拍摄 |
| 开源 = 创意无保护 | 低 | 黑客松阶段执行力即壁垒；日报+节律检测的数据积累是护城河 |
| 跨境收款/税务（若获奖） | 低 | 届时按 Devpost/W-8BEN 流程处理，不阻塞开发 |
